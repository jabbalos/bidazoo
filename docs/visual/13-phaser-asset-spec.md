# 13 Phaser Asset and Export Specification

Status: PROPOSED. All dimensions, atlas sizes, frame counts, and file-size budgets are GUIDANCE until
this package is reviewed. They are not architecture contracts.

Phase 1 is docs only. Nothing below is implemented. No runtime assets are generated yet.

## 1. Context from the repo

- Phaser `^3.90.0` (Phaser 3, per ARCHITECTURE.md).
- Today's character art is code-drawn into 320 px textures keyed
  `bz-character-{id}-{mood}` by `ensureCharacterTexture` in `games/zoo-sprint/src/characters.ts`.
- Client CSP: `img-src 'self' data:`, `connect-src 'self'`, `media-src 'self'`,
  `font-src 'self'`. All assets must be self-hosted. No CDN.
- Scenes: Boot, Menu, Run, Results. Boot checks the guest with the API and then starts Menu.

## 2. Location (approved for Phase 1)

```
games/zoo-sprint/assets/world-expedition/
  characters/{click,dino,koala,tarsier,eagle,bronco}/
  portraits/
  worlds/{basecamp,great-wall,petra,andes,maya,taj,nile,philippine-highlands}/
  ui/
  manifest.ts            (typed manifest, added in a later phase)
  PROVENANCE.md          (record of how each asset was made)
```

No `packages/assets` workspace dependency yet. Promote assets to a shared package later only when a
second real consumer justifies it.

## 3. Naming

- Files: the production spec (08) prints `character_click_idle_0001.png`, `ui_button_primary.png`,
  `ui_icon_star.png`, `node_complete.png`, `fx_confetti_0001.png`, `bg_rainforest_01.png`. These
  supersede the first draft's `{kind}-{id}-{variant}@{scale}` idea. Full proposal in
  [INGESTION-REPORT.md](INGESTION-REPORT.md) section 14.
- Two separate vocabularies (RESOLVED, owner October 12, 2026), so two namespaces:
  - Presentation / emotional states: `character_{id}_{state}_{nnnn}.png`, with `{state}` from idle,
    happy, tryAgain, thinking, cheer, discover, ready, proud, point, wave. Not every character needs
    every state.
  - Motion / gameplay animations (PROPOSED): `motion_{id}_{motion}_{nnnn}.png`, with `{motion}` from
    idle-loop, run, jump, land. More may be proposed later. `idle-loop` is a motion cycle and is
    distinct from the `idle` presentation pose.
- Texture keys: `bz-we-{kind}-{id}-{state}` for presentation and `bz-we-motion-{id}-{motion}` for
  motion (PROPOSED).
- Atlas frames: `{id}/{state}/{nnnn}` for presentation, `{id}/motion/{motion}/{nnnn}` for motion.

## 4. Asset types and proposed dimensions (GUIDANCE)

| Asset | Size | Format | Notes |
| --- | --- | --- | --- |
| Portrait sheet | 1536 by 1024, six cells of 512 | PNG with alpha | Selection, results, profile |
| Character atlas (per character) | up to 2048 by 2048, 256 px cells | PNG atlas + JSON | About 48 frames, lazy loaded |
| Fallback bust | 320 by 320 | Generated by the current code | Kept as fallback |
| Backdrop layers | 1920 by 1080 (far opaque; mid and near with alpha) | WebP | Plus a 1080 by 1920 portrait crop |
| UI atlas | up to 1024 by 1024 | PNG atlas + JSON | Icons at 128, panel parts |
| Hub scene | 3 layers, 1920 by 1080 | WebP | Basecamp |

Provide a 2x scale for high-density screens. The code already caps text resolution at devicePixelRatio 2.

## 5. Animation frame guidance

**Presentation states** (emotional; none is `run` or `jump`):

- `idle`: 6 frames at 8 fps, looping.
- `happy` and `cheer`: 8 frames, one shot.
- `tryAgain`: 6 frames, one shot.
- `ready`, `thinking`, `discover`, `proud`: 1 to 4 frames each.
- `wave`, `point` (Click only): 6 frames each.
- Every state has a single-frame static fallback for reduced motion.

**Motion / gameplay animations** (PROPOSED, separate from the above): `idle-loop`, `run`, `jump`,
`land`. Frame counts are not decided; more motion states may be proposed later. `tryAgain` tone is
gentle determination (see [07](07-expression-state-system.md)).

## 6. Budgets (GUIDANCE)

- First load, portraits plus UI atlas: under 1.5 MB.
- Per character atlas: under 700 KB.
- Per destination backdrop set: under 900 KB.
- Memory: a 2048 by 2048 RGBA texture is about 16 MiB on the GPU. Keep at most one character atlas
  plus one destination loaded at a time on phones.

## 7. Loading strategy (PROPOSED, not implemented)

1. **Preload:** during Boot, load the portrait sheet and UI atlas alongside the existing guest check,
   not blocking it.
2. **On selection:** lazy-load the chosen character's atlas.
3. **Destinations:** lazy-load a backdrop set on entry and release it on exit.
4. **Fallback:** on any load failure, use the existing code-drawn art, silently.
5. **No contract change:** the `Character` class API (`celebrate`, `wobble`, `setBustSize`) and
   `ensureCharacterTexture` stay as the fallback, so scenes do not change.
6. **Bundler:** reference files with `new URL('./x.png', import.meta.url)` so Vite fingerprints and
   copies them. The final approach is confirmed in Phase 3.

## 8. Export checklist

- sRGB, transparent background where noted, no embedded color profile surprises.
- Trim transparent edges; keep a consistent anchor (feet or bust center) per character.
- Pre-multiplied alpha is OPEN; decide once and document.
- Atlas padding of 2 px to avoid edge bleed.
- Dino sprite sheets must show exactly one backpack in every frame (and no second bag, chest pack,
  or duplicate); Koala must show no backpack.

## 9. Tests and gates

The hit-target geometry and `data-*` attributes the Playwright suite reads must not change. Any
asset-loading change runs the existing validators on the Studio PC before it is accepted.

## 10. Provenance and review (PROPOSED)

`PROVENANCE.md` records, for each asset, how it was made, who reviewed it, and the look-alike review
result for the Eagle "A", the Bronco star, and the destinations. Authoring toolchain, source file
storage (in or out of git), and any Git LFS use are OPEN.

## 11. Out of scope for this phase

Runtime code, loader implementation, replacement art, identity or account UI, API, database,
contracts, deployment, and `C:\BidaZoo-beta\app`.
